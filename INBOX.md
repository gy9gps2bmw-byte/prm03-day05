# Входящие обращения

Все сообщения ниже — учебные данные.

## A1 Пересечение бронирований

В версии demo-1 администратор подтвердил аудиторию 204 на время с 10:00 до 11:00 и с 10:30 до 11:30 одного и того же дня. Обе записи сохранились со статусом confirmed. Ожидалось отклонение второго подтверждения. Подготовленное свидетельство: samples/conflict-evidence.json.

## A2 Одна и та же аудитория занята дважды

Пользователь прислал один и тот же сценарий для аудитории 204 на 10:00–11:00 и 10:30–11:30 в demo-1. Это повторение A1, новых условий нет.

## A3 Выгрузка моих бронирований

Пользователь запрашивает CSV-файл только со своими записями за выбранную дату. Необходимо согласовать поля, порядок строк, заголовок и поведение при пустом результате. Для первой итерации реализацию не обещали.

## A4 Тёмная тема

Пользователь хочет переключатель оформления. Критериев пока нет. Ресурсы на ближайшую итерацию не выделены, запрос сохраняется для дальнейшего обсуждения.

## A5 Всё работает медленно

В сообщении нет информации о версии, действии, количестве записей и затраченном времени. Невозможно точно локализовать проблему. Нужно запросить недостающие сведения, а не назначать исправление наугад.

## A6 Нет описания формата данных

В README нет расшифровки полей в файле samples/bookings.json. Новый участник не понимает формат времени и допустимые статусы. Это можно исправить с помощью документа docs/data-format.md без изменения программы.
